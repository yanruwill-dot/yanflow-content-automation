# 焰流 YanFlow

把自动选题、内容生成、Image2 配图、发布风控、蚁小二 Dry-run、正式提交和结果核验放进同一个本地系统。

## 现在能做什么

- 从公开 RSS/Atom 来源抓取、去重和排序；本机没有 MiniMax 密钥时，自动改用 Codex 生成选题与正文。
- 生成公众号长文、小红书标题与正文，并保留来源和质量审稿。
- 调用本机公众号贴图工作台，以 Image2 优先生成 9 张 3:4 图。
- 新建任务时分别选择小红书和公众号账号；正式提交前也能切换当前任务账号。
- 提供“商业杂志、清爽阅读、宋式留白”三套排版，同时作用于公众号预览和下一次 Image2 图组。
- 实时显示抓取来源数、有效内容数、当前步骤、阶段百分比和总流程百分比。
- 对公开文案、图片重复、账号状态、单账号频率和历史任务做硬检查。
- 统一走 `Codex -> yxer/蚁小二 -> Hermes/API -> 小红书/微信公众号`。
- 自动流程默认只跑到完整 Dry-run；正式发布必须手工输入 `确认正式发布`。
- 将“本地成品、API 提交、平台状态、公开链接”分开记录，任务号不冒充已发表。

## 启动

在这个目录运行：

```bash
./start.sh
```

然后在 Codex 内置浏览器打开：

```text
http://127.0.0.1:8786/
```

也可以直接运行：

```bash
python3 server.py --port 8786
```

服务只监听 `127.0.0.1`，不会暴露到局域网或公网。

## GitHub Pages 线上版本

直接打开：

<https://yanruwill-dot.github.io/yanflow-content-automation/>

该版本由 GitHub Pages 托管，可以在浏览器里完成选题、内容生成、账号槽位切换、排版切换、贴图预览、发布预检和内容包下载：

```bash
npm install
npm run dev
```

GitHub Pages 版本不保存平台账号密码或发布密钥，因此“正式发表”会停在本地授权闸门；需要真实外发时，使用上面的 Python 本地版连接蚁小二或公众号授权通道。

## 屏幕适配

- 桌面与超宽网页自动使用全部可用宽度，不再留下大块无效黑色区域。
- 平板自动把指标、表单、流水线和内容卡片改为两列或单列。
- 720px 以下导航切换为顶部横排；360px 小屏仍保持无横向滚动。
- 单张内容配图在手机端居中放大，按钮、弹窗和提示不会越过屏幕边缘。

## 一次完整操作

1. 输入内容方向、读者和目标平台，选择每个平台的发布账号与排版。
2. 点击“启动安全自动流程”。
3. 在“LIVE PROGRESS”查看抓取、写作、配图和预检的实时进度。
4. 系统完成选题、内容、配图和发布 Dry-run。
5. 查看候选选题、正文预览、九图、风险检查和账号状态。
6. 如需换账号或排版，在“本任务发布设置”中修改；旧 Dry-run 会自动作废。
7. 只有新 Dry-run 通过后，“正式发布”才会解锁。
8. 输入 `确认正式发布` 后，系统才调用蚁小二正式提交。
9. 公开链接返回前，界面只显示“已提交”或“平台处理中”。

## 安全边界

这个系统不会宣称“100% 不封号”。平台风控由平台决定，任何工具都不能做真实保证。YanFlow 用以下规则降低可控风险：

- 不接管平台后台，不保存 Cookie，不做反检测或验证码绕过。
- 同一账号至少间隔 180 分钟，每日最多 3 次。
- 新任务图片与确认发布库、历史提交任务做感知哈希比对，近似图片直接拦截。
- 公开文案出现内部标签、站外导流、占位词或绝对化承诺时停止。
- 登录过期、验证码、实名、代理错误和平台审核都原样记录并停止。
- Dry-run 发布包会被固定；正式提交时如内容或图片改变，要求重新预检。
- 账号或排版变更会进入内容指纹并强制作废旧 Dry-run；已有平台任务号后设置锁定。
- 定时任务永远不能打开正式发布总开关。

## 依赖

- Python 3.9+
- Pillow
- Deno 与 `external/ai-trend-publish`
- `wechat-image-studio`
- `yxer` 3.x
- `codex_yixiaoer_autopublish.py`
- Node.js 22.13+（线上网页版本）

密钥从本机环境变量或 `~/.hermes/.env` 读取，只在后端进程使用，接口不会回显密钥。
